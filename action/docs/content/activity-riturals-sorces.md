# Источники процесса

> Из каких практик вытекают решения в `activity-rituals`: что взято, откуда и чем мы отличаемся от оригинала. Нужен, чтобы при пересмотре правила было видно, это адаптация проверенной практики или наше собственное решение.
>

## 2. Принципы (раздел 1)

| Принцип | Источник | Что взято | Чем отличаемся |
|---|---|---|---|
| 1. Слот — это привычка | [II], [AH], [DW] | Implementation intention «когда X, в месте Y, я делаю Z» резко повышает вероятность действия. У Clear — «время и место», у Newport — time blocking | Якорь — событие календаря с `activity_id`, время суток значимо |
| 2. Ритуал сортирует, думать — в спайке | [GTD], [XP] | В GTD processing — решение по каждому элементу, а не выполнение. Spike — отдельный таймбоксированный кусок исследования | Спайк выведен из разработки в личную систему; на выходе заметка из 4 пунктов вместо оценки задачи |
| 3. Новое — только ценой вытеснения | [Kanban], [PK], [SP], [4KW] | WIP-лимит, «stop starting, start finishing». У Burkeman — фиксированное число открытых проектов | Лимит по типу activity, а не по колонке доски. Редкая частота не выводит из лимита — это наше |
| 4. Решение из фиксированного набора | [GTD], [BuJo] | GTD: «actionable? → do / delegate / defer / trash / someday». BuJo migration: каждый пункт осознанно переносится или вычёркивается | Набор свой для каждого объекта (заметка, activity, step); «оставить как есть» ограничено |
| 5. Dropped — нормальный исход | [Quit], [4KW], [BuJo] | Отказ — навык, а не провал. Burkeman — принять конечность; BuJo — «не стоит переписывать — вычеркни» | — |
| 6. Пропуск — не долг | [AH], [Lally] | «Never miss twice». У Lally единичный пропуск не влиял на формирование привычки | Перенесено с привычек на ритуалы: два пропуска подряд — сигнал, а не катастрофа |
| 7. Правь, а не пересоздавай | Инженерная практика | Append-only история, soft delete | Наше, выросло из потери истории при пересоздании activity |

## 3. Жизненный цикл объектов (раздел 2)

| Элемент | Источник | Что взято | Чем отличаемся |
|---|---|---|---|
| Единый inbox, захват сразу | [GTD], [MB] | Capture: всё в один доверенный inbox. Masicampo & Baumeister: записанный план снимает навязчивые мысли о незавершённом | Inbox — служебная activity в MCP, а не отдельный инструмент |
| Мысль про существующую activity — сразу в неё | [GTD] | «Clarify / organize»: разложить по проектам | Разбор на входе, а не на ревью |
| Someday | [GTD] | Someday/Maybe list | Отдельной сущности нет; ревью раз в месяц, а не раз в неделю |
| Срок жизни someday (3 месячных разбора → expired) | [BuJo] | Migration: то, что переносится снова и снова, скорее всего не нужно | Порог 3 — наш |
| Счётчик всплываний `+1`, триггер спайка на 3 | — | — | Наше. Частота возврата мысли как прокси «нужно ли» |
| Спайк: таймбокс, выход — знание, go / no-go | [XP] | Spike — ограниченное по времени исследование, результат — решение, а не код | Заметка на выходе: «что изменится / что если нет / цена / первый шаг» — наша. Лимит 1 в неделю — наш |
| Вопросы спайка «через 3 месяца / если не делать / цена» | [Quit], [4KW] | Сравнение с opportunity cost, что вытесняется | — |
| WIP-лимит 6 / 3 на тип | [Kanban], [PK], [SP] | Лимит параллельной работы | Числа — наши, подобраны под портфель |
| `frequency_days` — мера внимания | [GTD], [MSP] | Разные горизонты требуют разной частоты ревью | Частота на уровне activity, а не горизонта; запрет использовать её как отсрочку — наш |
| Пауза с `deferred_until` и условием возврата | [GTD], [Quit] | GTD tickler file — вернуть в поле зрения в дату. Duke — «states and dates»: заранее заданные условия | Дата = «проверить», а не «вернуть» |
| Застревание: 2 периода → решение из набора | [Quit], [BuJo], [AH] | Kill criteria, заданные заранее, а не в моменте. Migration как вынужденное решение. «Never miss twice» | Определение застревания и запрет «снизить частоту» — наши, выросли из 4 циклов греческого |
| Steps как next actions | [GTD] | Next action — следующее физическое видимое действие | До 3 открытых one_time вместо одного next action на проект; repeatable steps — наше |
| Step висит 2 ретро → слот / мельче / удалить | [GTD], [TH] | Слишком крупное действие не начинается — разбить. Fogg: уменьшать до «starter step» | Порог 2 ретро — наш |
| Achievement, прогресс-бары | [GG] | Goal-gradient effect: чем ближе видимый финиш, тем выше усилие | Achievement — не цель activity, а геймификация аспекта; лестница ~×2 и лимит 6 — наши |
| Проваленный achievement фиксируется как есть | [Quit] | Честная фиксация исхода, без переписывания задним числом | — |

## 4. Ритуалы (раздел 3)

| Элемент | Источник | Что взято | Чем отличаемся |
|---|---|---|---|
| Иерархия день / неделя / месяц / квартал, каждый уровень опирается на нижний | [MSP], [GTD] | Multi-scale planning; GTD Horizons of Focus | Ежедневного ритуала нет, месячный — блок недельного |
| Нет ежедневного ритуала, утренний взгляд 2–3 мин | [GTD] | «Engage»: смотреть на календарь и next actions | Отказались от ежедневного планирования по [MSP]; shutdown [DW] отложен |
| Недельный ритуал | [GTD], [Retro], [GR] | GTD Weekly Review: get clear → get current → get creative. Ретроспектива: собрать данные → инсайты → решить → закрыть. Meier: Monday Vision / Friday Reflection | Три фазы «разгрести → текущее → следующая неделя» — сплав GTD и ретроспективы |
| Единая картина вместо «как прошла неделя?» | [Retro] | Фаза «gather data» до обсуждения | Данные собирает агент из MCP и календаря |
| Тема недели | [GR], [SP] | Rule of 3 — несколько результатов на неделю; фокус на главном | Один вопрос «что должно случиться, чтобы неделя была успешной» |
| Слоты только под тему недели | [DW], [MSP] | Time blocking под приоритеты, а не под список | — |
| Итог сессии в 70 | [Retro] | «Close the retrospective» — зафиксированный выход | Хранится как progress point |
| Месячное ревью портфеля | [BuJo], [Kanban] | Monthly migration; регулярный пересмотр WIP и потока | Встроено в недельное, а не отдельная сессия |
| Баланс по life parts | [GTD] | Areas of focus / responsibility — проверка, что ни одна область не заброшена | Только сигнал, без автоматической перекройки |
| Квартальное ревью: связь с целями | [MSP], [GTD] | Квартальный горизонт; Horizon 3 (цели на 1–2 года) | Переосмысление трека — в спайк, не на ревью |
| Квартальное ревью процесса | [Retro] | Ретроспектива на сам процесс | — |
| Таймбоксы ритуалов | [Retro], [XP] | Timebox как ограничитель | — |
| Минимальная версия ритуала | [TH], [AH] | Сделать настолько маленьким, чтобы не пропустить; «two-minute rule» Clear | Своя минимальная версия у каждого уровня |

## 5. Режим деградации и мета (разделы 6–7)

| Элемент | Источник | Что взято | Чем отличаемся |
|---|---|---|---|
| Не наверстывать, следующий по программе | [AH], [Lally] | Пропуск не ломает привычку; ломает серия пропусков | — |
| 2 пропуска → минимальная версия + «что мешает?» | [AH], [TH] | «Never miss twice»; при срыве уменьшать, а не усиливать | Вопрос «что мешает» — вход для квартального ревью процесса |
| Разовый сдвиг месячного и квартального | — | — | Наше: цикл длинный, полный пропуск дорог |
| Отложенные альтернативы с сигналами пересмотра | [ADR] | «Considered options» + условия, при которых решение пересматривается | Сигнал пересмотра у каждой альтернативы — наше |
| Changelog процесса | [ADR] | Решения процесса документируются с датой | — |

## 6. Контракт с агентом (раздел 5)

Прямого источника нет. Опирается на общие принципы human-in-the-loop: агент собирает данные и подсвечивает, решения принимаю я. Список «никогда» вырос из конкретных сбоев в прошлых сессиях: achievement трактовался как финишная черта, steps придумывались, WIP-лимит обходился частотой.

## 7. Рассмотренные и не взятые практики

| Практика | Источник | Почему не взяли |
|---|---|---|
| «Организуй, когда трогаешь» (just-in-time) | [BASB] | Противоречит явному месячному и квартальному разбору; убран из принципов |
| PARA как структура | [BASB] | Activity + life parts уже покрывают projects / areas; ресурсы и архив живут вне системы |
| Ежедневный shutdown | [DW] | Отложен до сигнала (`rituals.md`, 7.2) |
| Ежедневная сессия планирования | [GR], [MSP] | Слоты в календаре уже маршрутизируют день; дорого по времени |
| Someday на еженедельном ревью | [GTD] | Слишком частый разбор; перенесено в месячный |
| Один next action на проект | [GTD] | Слишком строго для проектов с параллельными ветками; лимит 3 |
| OKR | Grove, *High Output Management* (1983); Doerr, *Measure What Matters* (2018) | Для личного портфеля избыточно; квартальная связь с целями закрывает ту же потребность |
